# Syllabus: concepts, resources and external AI

Syllabus complements Practice (the DSA/SQL catalog) and Plan (scheduled outcomes). It is not limited to software: learning areas are free text and the Role track supports other professions.

## Learn → practice → explain

A new workspace includes **33 unstarted topics** covering:

- Python collections, functions/scope, exceptions, files, classes/composition, typing, generators/decorators, environments/testing and async I/O.
- DSA reasoning/complexity and SQL/query-plan foundations.
- APIs, security, networking, storage, distributed-system trade-offs, design exercises and observability.
- LLM foundations/attention, structured outputs, tool use, chatbot state/memory/streaming, RAG ingestion/hybrid retrieval, evaluation, injection resistance, deployment and MCP.

Each topic has a practical objective, prerequisites, resources, status, evidence/notes and an optional **linked Plan task**. Open resource links directly from the topic. Official docs, course pages and video collections are suggestions, **not copied paid content or guarantees of current availability**. Some links describe a whole course/channel rather than one video. Review for your baseline and learning preferences; add a more specific video if useful. Nothing plays/downloads automatically.

The starter curriculum is a bounded starting point, not a certification or exhaustive career-readiness promise. Existing installations do **not** silently gain a syllabus: use **Review starter syllabus**, review and apply it. Existing topic IDs are skipped. If you have removed a prerequisite topic, restore it or remove/update dependent references before importing another batch.

### Time accounting

Multiple topics can support one broad plan outcome. Their linked `taskId` points at the same outcome; **log a real session once in Today**, optionally selecting that outcome. Topic status does not invent session hours, mark the task done or verify a readiness gate. Review the broad task estimate if the detailed syllabus reveals more work than expected. Additional tasks generated by AI increase remaining scope and can move the forecast later.

Manual editing supports topic progress, evidence, resources, links and prerequisite IDs. Cycles, missing IDs and unsafe URL schemes are rejected. Deletion is explicit and fails when another topic still depends on the record.

## With no AI API

1. Set target role, capacity and baseline details in Settings. Open Syllabus.
2. Click **Build fresh context prompt**. Review and edit the entire text. Add your specific JD, current skills, goals, preferred resources and constraints.
3. Copy or download `syllabus-prompt.md`, then give it to your chosen external AI. Sending it to a cloud AI shares that text with that provider; the app does not perform this step.
4. Ask that AI to follow the requested Markdown/JSON contract. Save its answer as `.md`, or paste the response.
5. **Import AI response Markdown** / **Validate & preview Markdown** validates the data before any edits. Review the summary, new records, estimates and resource URLs, then **Apply reviewed syllabus**.
6. Export a fresh prompt for another batch or after any workspace changes.

A saved prompt is an editable document, **not a magical live template**. Loading it keeps your wording. Building a fresh prompt refreshes saved context. Saving the prompt advances only its embedded revision to account for that prompt-only save; other changes make old response revisions stale. If stale, regenerate from fresh context rather than editing revision numbers to force old assumptions through.

Context includes target role, capacity, bounded task/topic titles and statuses, and gate criteria; **contacts, raw private evidence, keys and attachments are not automatically included**. Do not put employer/client secrets into the editable prompt. All text sent to an in-app provider is visible in the prompt first.

## With a configured AI

Set a local Ollama or compatible provider in Settings, then build/edit the prompt and choose **Generate with configured AI / retry**. The provider returns the same strict data format, parsed server-side. Invalid output, missing provider or a stale revision is a visible error; no edits are applied. Retry is explicit and can incur another provider charge.

This action **does not browse**. For online, evidence-grounded preparation, first use the consent-based Research workflow, review its sources, and paste relevant public excerpts/URLs into the syllabus prompt. That workflow remains available for any profession. Syllabus prompts explicitly tell a browsing-capable external AI to verify resources where possible, and otherwise to label suggested links unverified. Schema checks are not a truth/relevance audit; verify important claims yourself.

## Markdown exchange v1

The response is Markdown containing **exactly one** fenced block named `career-syllabus`:

````md
# My proposed syllabus

```career-syllabus
{
  "format": "career-syllabus",
  "version": 1,
  "baseRevision": 4,
  "summary": "Assumptions, learning scope, resource checks and additional hours",
  "operations": [
    {
      "kind": "topic",
      "value": {
        "id": "new-functions-topic",
        "title": "Functions and scope",
        "area": "Python foundations",
        "track": "Backend",
        "objective": "Write and test a closure; explain late binding and mutable defaults.",
        "prerequisites": [],
        "taskId": "python",
        "status": "Not started",
        "evidence": "",
        "notes": "Adapt to baseline",
        "resources": [
          {
            "title": "Python control flow tutorial",
            "url": "https://docs.python.org/3/tutorial/controlflow.html",
            "kind": "Docs",
            "notes": "Suggested official resource; verify availability"
          }
        ],
        "updatedAt": "2026-10-01T12:00:00Z"
      }
    }
  ]
}
```
````

The example's revision and existing `python` task reference are illustrative: use the actual prompt context. Up to 300 operations / 2 million Markdown characters; generation is instructed to keep batches small (8–12 topics, at most 30 operations in-app). Allowed kinds: **topic, task, note**, all with new IDs. Generated topics must be Not started, tasks todo, evidence empty, and notes cannot attach files. Existing task IDs can be referenced without creating a second estimate. Import never overwrites existing records, deletes work, fabricates sessions/attempts or edits claims/profile. Full validators reject cycles, duplicate operations, unknown fields and dangling references. Markdown HTML/code is never executed or rendered as trusted HTML.
