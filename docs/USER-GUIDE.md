# A practical weekly workflow

## Start from evidence, not an ideal calendar

The default syllabus is a starting template for backend/applied-AI switching. Change role, estimates and tasks to suit your baseline. Keep core interview requirements; reduce duplicated learning before cutting important topics. If you already completed a project, enter its real evidence rather than rebuilding it because a template says so.

Set 18–20 hours/week if realistic, 19 by default. Allocate that same budget to coding/revision, backend/AI, systems/explanation and career/mock work. For example: DSA 7.5, backend/AI 6, systems/speaking 3, career 2.5 = 19. SQL and coding mocks must be assigned inside these totals, not extra invisible hours. This allocation is a suggestion, not a mandatory fixed timetable.

## Concepts and resources, not only DSA

Open **Syllabus** for Python foundations, backend/system design and AI/chatbot concepts. Learn from each topic's linked resource, implement its exercise, then record a concise explanation/evidence. Link a Plan outcome and log time **once** in Today. Existing users can review/apply the starter syllabus; it does not overwrite their activity. Customize or generate a role-specific batch using the [editable prompt / external Markdown workflow](SYLLABUS.md).

## Working in Excel

Export **Settings → Excel tracker**, edit plain-value data sheets, then import for a reviewed reconciliation. Dashboard is first; Profile, Syllabus/Resources, all trackers and long source/prompt documents are included. Same-workspace conflicting edits are rejected, not silently overwritten. Mark `_delete=YES` for explicit deletions; merely removing a row does not delete the app record. Export fresh after applying. A different-workspace import requires replacement confirmation. Full workbooks include hidden personal data/assets—do not treat them as sanitized shareable progress reports. [Full contract](DATA.md).

## Daily: under two minutes of administration

1. Work in a meaningful block, then write one Quick log with duration and result.
2. Optionally link an outcome so actual time can calibrate it later.
3. Review the proposed record(s); Apply once. If duration or result is missing, the parser will not invent it.
4. Keep one useful note when necessary; screenshots optional. A zero-hour day needs no entry and creates no debt.

Use a separate entry for each question/session. `1h 30min` works; spell units and separate them clearly. Practice-only “Log attempt” tracks recall, **not session hours**. Quick log can create both without double counting. Correct a mistaken recent session using Edit; all data sheets are also available in Excel.

## Weekly: 15-minute review

- Look at honest actual hours and remaining scope; don’t chase a streak.
- Close a task only when its acceptance outcome is met. Add evidence, not a ceremonial checkbox.
- Review due DSA/SQL questions and weak patterns; record independent/hinted/failed honestly.
- Choose a coding outcome, a defensible project artifact and a spoken explanation.
- Move unfinished outcomes forward. If overload persists, lower capacity or increase estimates. No sleep repayment or double quotas.
- Apply to relevant roles once their gates are ready; it is not necessary to complete every extension. Conversely, a calendar date is not permission to fabricate readiness.

## Resume and interviews

Keep official title/company/dates in Profile. Add individual Experience/Project/Skill claims with proof or a defensible explanation. Current resume uses Verified claims only. Future-state mode shows intended completed-style wording with a warning; use it as an acceptance checklist, never submit before it is true.

For incidents, prepare actual symptom, impact, timeline, hypotheses, evidence, your role, recovery, root cause versus contributing factors and prevention. Do not invent a timeout, duplicate batch or metric from a sample script. An honest hook invites deeper discussion: “I can walk through one integration design or one incident if useful.” Answer the interviewer’s question first.

When unsure: say what you do and don’t know, ask one useful clarifying question, reason from a correct baseline, and describe how you would verify. Don’t repeat five polished excuses instead of engaging. Stories are editable; optional AI uses supplied facts and placeholders.

## Jobs and source research

Record India eligibility and time zones, employee/EOR/contractor arrangement, actual engineering ownership, on-call/workload, mentor/review support, salary fixed versus variable/CTC, notice/buyout and next action. A foreign logo is not evidence of healthy workload or global remote eligibility.

Save primary source URL/date/excerpt and limitations. A vacancy can close; a search snippet can be stale. Generic salary numbers are not a personal entitlement or guaranteed offer. The single-proposal AI button synthesizes supplied sources. For live bounded search, role-specific planning and saved retries, use Research → Research & generate plan; see [AI workflow](AI.md).

## Buddy use

Each person owns their local workspace. Export sanitized Excel, import to Google Sheets and exchange viewer/commenter links. Read each other’s notes and discuss one useful takeaway weekly. No auto-sync or shared credentials. Images are best kept in the app/full backup; Google-specific objects do not import as local attachments.

## Editing a real resume source

Resume → LaTeX editor & PDF → Import original .tex. Review source, install the optional compiler, enable first-use package downloads, compile, then enable live PDF if desired. Clean PDF output has no app watermark. Source and structured claims remain independent. Full setup and trust requirements: [LaTeX studio](LATEX.md).
